    Getting Started

    5 MIN READ Get Neco DQ running in minutes

    1. Install

    pip install neco-dq-framework

    Clusters with internet access can install straight from PyPI with the same command.

    If your Databricks environment has no outbound internet, or you want to pin an exact version, host the wheel yourself on a Unity Catalog Volume. Download it from PyPI once:

    pip download neco-dq-framework --no-deps -d ./wheelhouse

    Upload the resulting .whl to a Volume your workspace can read, then install it:

    %pip install /Volumes/<catalog>/<schema>/wheelhouse/neco_dq_framework-X.Y.Z-py3-none-any.whl

    2. Create Config

    Save this as /path/bronze_suite.yaml:

    bronze:
  tables:
    - catalog: your_catalog
      schema: your_schema
      table: your_table
      checks:
        freshness:
          enabled: true
          timestamp_column: batch_ingestion_at
          max_delay_hours: 24

        schema_drift:
          enabled: true
          expected_columns:
            project_id: string
            record_id: string

    3. Run

    from neco_dq.runner import run_dq

results = run_dq("/path/bronze_suite.yaml")

    Your First Validation

    Step 1: Create Configuration

    For production, use the modular configuration structure:

    /path/config/
├── global/
│   └── policy.yaml
└── suites/
    └── bronze/
        ├── suite.yaml
        └── test_groups/
            └── ingestion.yaml

    policy.yaml:

    dq_policy:
  block_test_suites:
    profiling: false
    bronze: true
    silver: true
    gold: true
    great_expectations: true

  alerts:
    slack:
      enabled: true

    suite.yaml:

    default_checks:
  record_count:
    enabled: true
    severity: warning
    blocking: false

  table_freshness:
    enabled: true
    severity: warning
    blocking: false
    max_staleness_days: 2

    ingestion.yaml:

    tables:
  - catalog: my_catalog
    schema: my_schema_bronze
    table: answers
    checks:
      mandatory_fields:
        enabled: true
        severity: critical
        blocking: true
        columns:
          - user_id
          - record_id
          - response_date

      schema_drift:
        enabled: true
        severity: critical
        blocking: true
        expected_columns:
          user_id: string
          record_id: string
          response_date: timestamp
          rating: integer

    Configuration options

    For simpler use cases, you can use a single YAML file. See Single-File Configuration. For multi-environment deployments (dev/staging/prod), see Profiles.

    Step 2: Run Validation

    from neco_dq.runner import run_dq

results = run_dq(
    "/path/config/",
    run_suites=["bronze"]
)

    Exit Codes

    Exit Code Status Meaning
    0 PASS All checks passed
    10 WARN Non-blocking failures only
    20 FAIL One or more blocking failures
    99 SYSTEM_ERROR Invalid configuration or system error

    What if a check fails?

    A failing check doesn't just print FAIL: it attaches statistics and an investigation query template (never row values) so you can find the offending rows. See Debugging Failures for how to read failure_stats and investigation_query.
